## 1. 创作与档案：先发现生命，再决定画面
1. 从世界的存在规则、生态压力与能源/物质来源出发，推导新的生命形式、结构或维持机制、习性和局限。**不做生命类别轮换配额；不先找一个漂亮镜头再补故事**。
2. 建立**一物种一独立UTF-8 TXT**：连续唯一编号、固定中文名/英文名、世界、生态、规模、形态/存在DNA、机能、代谢、生命周期、因果解释与未知处。
3. 依TXT模板V3保留17节；第15—17节写物种专属视觉边界与可供参考的灵感，**不是不可修改的摄影剧本**。硬性不变的是当前生命身份与内部世界规律。
4. TXT创建后上传Google Drive并读回/列表核验。未成功读回时记“TXT未核验”，禁止跳过并假设成功。
5. 对于已有TXT的物种，先核对云端事实和编号；**不因执行新版本而擅自重写已存在档案**。

## 2. 单物种生成事务（核心执行算法）
**一项事务只处理一个物种。** 接收的任务参数仅应是：
`species_id`、`txt_file_id_or_verified_path`、`requested_views`（通常1、2、3）。
编号、路径和物种名称必须能从真实TXT回读核对；无法核对就终止本物种生成。

### 2.1 当前物种内部步骤
A. **唯一读取**：只读取这一物种的完整TXT。内部理解其生态、形态DNA、能量机制、局限与可观察事件；不读取同日其他五种物种内容来创作本图。  
B. **自由发现**：像异世界自然学家那样重新思考三幅不同且合乎世界规则的画面。三个使命固定：图一认识、图二理解、图三想象与未来人类的关系；具体画面自由。  
C. **锁定视觉DNA**：建立仅属于当前物种的简短内部检查项（3—7项或非实体的稳定识别模式）：数量、几何形态、连接位置、颜色、尺度、特殊机制。  
D. **逐图产生指令**：每个视图各写**一条完整、独立的视觉描述**，只含当前物种名称与事实、当前情节、构图与风格、规格、编号与签名；不包含其他物种内容、任务管理信息、失败复盘。**这一步是创作语言翻译，不是固定情节套模板**。  
E. **生成一次**：每个视图各一次独立生成。一个请求对应一个物种、一个视图、一张完整画面，不用一张多联图裁切冒充三图。  
F. **实际验收**：核验真实图片是否存在且与当前物种TXT、视觉圣典相符；不合格只记录失败/待重绘，**本轮不暗中重试**。  
G. **完成本物种**：展示三张候选及失败槽位供用户审核；登记实际状态；然后才释放本物种创作范围并切换另一TXT。

### 2.2 生成前身份检查（防串扰）
在**可审查最终实际传给图像模型的请求内容**的接口中，发起调用前必须检查：
- 唯一物种编号、中文名、英文名与当前TXT一致。
- 必要DNA与当前故事逻辑一致，不存在其他物种名称、器官、世界名或混淆的身份信息。
- 没有全批清单、06:xx日程、进度图、报告、历史事故与多物种拼版指令。
- 图一风格指向视觉圣典中的008/009/010美术语法，而**非复制其生命造型**。
- 图二为自然行为；图三为符合生命局限的人类未来关系。

**关键技术限制：** 当前某些聊天内图像工具可能自行推导隐藏绘图指令，使用者不能检查最终请求。此时上面的检查只能约束我们可见的构思，**不能声称实现最终指令的硬性预检**。若工具不提供可审查的最终请求、也不能隔离自动上下文，应将其标注“生成器上下文未技术验证”，对输出进行严格目视检查；发生明确物种串扰时及时停止，不凭加长否定提示词承诺修复。

## 3. 三视图画面规则：精简引用，不在此重复整份视觉手册
- **图一 / 认识生命**：遵照《万象视觉圣典》唯一现行图一规则：以008、009、010**原图**为风格参考。**可信高精度发现现场 + 有内容的复古实体研究纸本 + 实际观察特写 + 博物学手绘/剖面 + 自然手写标注 + 自由构图**。**001不是当前图一美术参考**。不强制整图纯纸，也不把贴纸边框的商业CG海报当作自然史笔记。
- **图二 / 理解生命**：沉浸式自然纪录，表现由生命习性与生存机制导致的真实事件；不复制图一资料卡。
- **图三 / 想象未来**：人类行动/设施与该生命形成可信关系，可以亲近也可以避让、保护或冲突；不固定科考员触碰。
- 三图使用相同视觉DNA，记录不同瞬间；画幅**横向3:2、目标1536×1024 PNG**，编号、中英文名称、`Azhou&Lbai`检查一致。无法保证图中文字正确时标记待校正，禁止凭空添加TXT未支持的科学数值。

## 4. 审核、归档与状态
- **TXT**：完整写入后可直接上传云端并验证。
- **PNG**：须先展示供用户审核；用户明确批准图/物种/批次（可明确放宽小细节）后方能上传云端正式图库。
- 一图只记录一种真实状态：`未尝试` / `生成失败` / `有效待审` / `用户批准` / `已上传待核验` / `已上传且核验`。失败或未尝试不能算完成。
- 云端上传后列表或读回验证文件名、数量及物种归属；020等既有已上传作品不因本版启用而重复上传。
- 发生**连续两次明显跨物种错误或任务看板错误**，立即终止本轮后续绘图并记录；修订需新的用户授权。
- 生成工具限额、任务重叠和图像接口不足必须如实报告；不得把计划进度或图上标注当作完成证明。
- 已批准的旧作品和旧TXT不被新规则自动覆盖。

## 5. 工程边界：调度、创意、图片与汇总绝不混写
| 模块 | 可以读取 | 不能传给图片生成器 |
|---|---|---|
| **调度** | 物种编号、TXT真实ID、状态索引、时间表 | 当天六种名单、执行进度、调度文本 |
| **生命创作** | 当前世界与物种TXT、宪章原则 | 其他物种全文、历史事故文本 |
| **单图美术** | 当前物种DNA、当前视图创意、视觉圣典相关风格 | 其他物种内容、跨物种图片和看板 |
| **汇总** | 工具实际运行、上传与核验回执 | 任何作为“艺术内容”的完成率或事故报告 |

**风格参考是特殊例外**：图一允许单独载入008/009/010原始图片作为纯风格参考，但当前物种身份、形态、器官和环境只能来自当前TXT。工具若不能做到参考图内容隔离，应采用视觉圣典的文字特征并明确风险。

## 6. 成功判定与最小质量门
每物种完成后检查：
1. TXT实际存在、编号与中英名一致、内容足以支撑生命的存在机制；
2. 三图真实独立，当前生命无混种，视觉DNA稳定；
3. 图一符合008—010的发现记录风格，图二表达自然行为，图三展示可信未来关系；
4. 每图的名字、署名、重要结构、格式与文字事实已检查，无法确认处注明；
5. 上传动作有用户许可、真实云端回执和读回，不夸报完成。

如验收不通过，返回具体失败槽位及原因；**不自动修改当前物种事实或创造替代物种**。
